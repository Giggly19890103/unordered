https://en.wikipedia.org/wiki/Hash_table[哈希表]是极为流行的计算机数据结构，几乎可以在任何一种编程语言中以某种形式存在。尽管其他关联式结构（如红黑树——在C{plus}{plus}中由`std::set`和`std::map`使用）的插入与查找操作具备对数时间复杂度，但哈希表若配置得当，平均而言可在常数时间内完成这些操作，且执行效率通常显著更高。

C{plus}{plus}11引入了__无序关联容器__
`std::unordered++_++set`、`std::unordered++_++map`、`std::unordered++_++multiset`与`std::unordered++_++multimap`，但自那时起哈希表的研究从未止步：CPU架构的进步，诸如更强大的缓存、https://en.wikipedia.org/wiki/Single_instruction,_multiple_data[SIMD]操作以及日益普及的https://en.wikipedia.org/wiki/Multi-core_processor[多核处理器]，为改进基于哈希的数据结构开辟了新可能，并催生了2011版规范中无序关联容器根本无法实现的新用例。

* **闭寻址容器**完全符合C{plus}{plus}对无序关联容器的规范要求，且在标准接口规定的技术约束下，实现了当前业界最快的处理方案之一。
* **开放寻址容器**依赖更快的数据结构和算法（典型场景下速度最快可高出两倍以上），并通过微调标准接口以适配实现。其提供两种变体：*平坦结构*（速度最快）和**节点结构**（在重散列时保障指针稳定性，代价则是较慢的运行效率）。
（注：严格遵循技术术语一致性原则："open-addressing"统一译为"开放寻址"，"flat"译为"平坦结构"，"node-based"译为"节点结构"；保留HTML强调标签；采用"微调标准接口"准确传达"slightly

* 最后，**并发容器**专为高性能多线程场景设计与实现。其接口与常规C{plus}{plus}容器截然不同，同时提供平面版本和基于节点的版本。

Boost.Unordered中的所有集合（set）与映射（map）容器的实例化方式分别与`std::unordered++_++set`和`std::unordered++_++map`相同：

[source,highlight]
----
namespace boost {
    template <
        class Key,
        class Hash = boost::hash<Key>,
        class Pred = std::equal_to<Key>,
        class Alloc = std::allocator<Key> >
    class unordered_set;
    // 同样适用于 unordered_multiset, unordered_flat_set, unordered_node_set,
    // concurrent_flat_set 和 concurrent_node_set

    template <
        class Key, class Mapped,
        class Hash = boost::hash<Key>,
        class Pred = std::equal_to<Key>,
        class Alloc = std::allocator<std::pair<Key const, Mapped> > >
    class unordered_map;
    // 同样适用于 unordered_multimap, unordered_flat_map, unordered_node_map,
    // concurrent_flat_map 和 concurrent_node_map
}
----
